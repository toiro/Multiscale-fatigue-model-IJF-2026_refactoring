# Legacy CTSD NaN Verification Plan

## 目的

`multiscale-fatigue-model/Multiscale_fatigue_model.py` の旧プログラムを実行し、
`N50R_CS_T50`・**135 MPa** で CTSD に NaN が発生するか確認する。
発生した場合は入力と計算経路を保存し、
[B_Smooth_T16 の報告](../03_troubleshooting/B_Smooth_T16_ctsd_nan_report.md) と同じ機序かを調べる。
同報告では旧実装の局所4関数を同一入力で評価しているが、旧プログラム全体は実行していない。
今回は N50R_CS_T50 の旧プログラム自身が生成した入力を対象とする。

進捗は [legacy_ctsd_nan_todo.md](legacy_ctsd_nan_todo.md) に記録する。

## 対象と前提

- 実行対象は `Multiscale_fatigue_model.py`。`.org.py` は今回の実行対象にしない。
- 応力は全段階で135 MPaに固定する。旧コード既定の150・175 MPaや、
  `resources/configs/N50R_CS_T50_ctsdnan.json` の5応力・4試行をそのまま使わない。
- 旧コードは RuntimeWarning を抑制しているため、警告の有無では判定しない。
- 通常 CSV は採用候補の履歴なので、非採用候補を含む実行中の CTSD を直接観測する。
- 既存の `verification/diagnose_ctsd_nan.py` は整理版での捕捉が主体である。
  旧実装の直接実行用の入口を別途用意する。
- 既存の `verification/replay_ctsd_nan.py` は未到達粒界の混入を前提にした assert を含む。
  N50R の原因を決めつけず、別の発生経路も記録できる再評価を用意する。

## 変更範囲と実行方法

- 追加先は原則 `verification/` と `scripts/verification/`。旧コードと `src/` の計算核は変更しない。
- `.ps1` から `.venv\Scripts\python.exe` で旧コード実行用ラッパーを起動する。
- 既存の `MFM_RANDOM_SEED`、`MFM_SIGMA_NOM`、`MFM_ITERATIONS`、`MFM_N_SYMM`、
  `MFM_MAX_ACTIVE_ELEMENTS`、`MFM_OUTPUT_DIR` を利用する。
  環境変数は実行前の状態を保存し、終了・例外時に復元する。
- 関数復帰時のトレース等により `CTSD()` と `evalCTSD()` の戻り値を観測する。
  トレース対象は旧ファイルと必要な関数に限定し、観測負荷を抑える。
- 計算式、分岐、丸め、乱数呼び出し順序、通常 CSV 形式、既存 print を維持する。
  NaN の置換、粒界範囲の補正、候補棄却による継続は行わない。
- 入力ファイルと既存 cache の配置・由来を確認する。準備や実行が旧ディレクトリに
  cache 等を書き込む箇所は事前に確認し、必要なら入力一式を作業用ディレクトリへ複製する。
  その場合も旧コードの内容と入力データは保持し、使用した実体を記録する。
- 既存の作業中変更と出力は上書きせず、実行ごとに専用の出力ディレクトリを使う。

## 段階的な検証

| 段階 | 応力 | seed | 試行数 | 対象要素 | 対称領域 |
| --- | --- | --- | --- | --- | --- |
| 1: 捕捉機構の確認 | 135 MPa | 42 | 1 | 応力順位の上位1要素 | 1 |
| 2: 範囲の拡大 | 135 MPa | 42 | 1 | 旧コード既定の対象範囲 | 4 |
| 3: 追加探索 | 135 MPa | 追加seedを実行前に記録 | 必要に応じて拡大 | 段階2と同じ | 4 |

1. 段階1で最初の非有限 CTSD を保存し、診断用の停止として終了する。
2. 未検出の場合だけ段階2へ進む。段階2も最初の非有限値で捕捉・停止する。
3. さらに未検出の場合は、追加seed、試行数の順に範囲を広げる。
   無制限には探索せず、各ジョブのseed一覧・試行数・時間上限を実行前に記録する。
   中断や例外は完走と区別し、実際に観測できた範囲を残す。

乱数は各実行の開始時に Python random と NumPy の両方へ設定し、途中で再seedしない。
要素数や対称領域数を変えると後続の乱数列も変わるため、段階間を同じ乱数履歴の延長とは扱わない。
任意の要素・試行へ直接飛んだ実行を、通常実行の当該位置の再現とは呼ばない。

## 捕捉・記録する情報

- 実行日時、旧コード・入力・cache のパスとハッシュ、Python・NumPy・SciPyのバージョン。
- 実効パラメータ、seed、応力、試行番号、要素順位と実要素番号、対称領域、粒候補、評価点。
  各 index の0始まり／1始まりを明記する。
- CTSD とその非有限値の種類（NaN / inf）、`a`、`c`、`n`、粒界位置、摩擦強度比、
  せん断応力、`DataImport.AA`。可変配列は検出時点でコピーして保存する。
- 同じ評価点の根探索入力・戻り値と、粒層更新・根探索要否の判定に使用した値。
- CTSD評価回数、評価した候補・要素等の範囲、完走／検出停止／例外／時間上限による中断。
  `CTSD()` の呼び出しと `evalCTSD()` の評価回数は区別する。
- 標準出力・標準エラー。非有限値はJSONで扱える明示表現にし、再評価時に復元する。

保存先は `outputs/troubleshooting/N50R_CS_T50_legacy_ctsd_nan/` 以下の実行別ディレクトリとする。
捕捉入力、実行概要、局所解析、通常CSVを区別して置き、未検出でも実行概要を保存する。

## 保存入力の局所再評価

1. 旧コードの AST から必要な `safe_arccos`、`CCn`、`gg`、`CTSD` を取り出し、
   保存入力で CTSD の非有限値を再現する。整理版への依存は必須にしない。
2. 捕捉した根探索の引数で `CCn` を再実行し、保存したすべり帯長さと比較する。
   根探索を経由しない分岐の場合は、その事実を記録し、根探索由来と仮定しない。
3. 積分対象粒界と `c` を比較し、`gg()` の `x == ad` による調整も含めて、
   実際の平方根引数・対数引数と入力の有限性を確認する。
4. 未到達粒界の角度項が根探索では0になる一方、CTSD積分では評価されるか確認する。
5. B_Smooth の機序と一致／別原因／未確定を区別する。
   到達粒界だけの評価を行う場合は原因切り分け用の反実仮想と明記し、修正値にはしない。

## 観測が計算を変えないことの確認

- 完走できる同一の軽量条件で、観測あり／なしの旧プログラムを別プロセスで実行し、
  通常 CSV の形式・数値・可能ならバイト列と終了時の乱数状態が一致することを確認する。
- 捕捉停止する実行では、停止以後の通常結果が存在することを要求しない。
  完走可能な条件が得られない場合は、停止までの計算値と乱数状態の比較に切り替え、限界を記録する。
- 既存の B_Smooth fixture 等で捕捉・再評価の検出経路も軽量確認する。
  この結果と、N50Rで発生を確認した結果は区別する。
- 実装後は compileall（`src verification`）、`Invoke-StaticAnalysis.ps1`、
  `Invoke-ParameterConditionVerification.ps1`、`Invoke-SmokeVerification.ps1` を基本とする。
  失敗時は今回の変更によるものか既存状態かを記録する。
- 乱数順序・CSV不変性の引き渡し前確認は、旧実装を再実行する比較で行う。
  旧実装と整理版の既存 full baseline 比較が必要な変更を行った場合は
  `Invoke-BaselineComparison.ps1` も実施する。baselineを回す単位ではsmoke / legacy miniは省略可能。
- `parameters.py`、`paths.py`、`context.py`、`resources/` を変更する場合は
  `Invoke-ConditionPreflight.ps1` を実施する。今回の基本方針ではこれらを変更しない。
- 文書のみの段階では計算・静的解析は実行しない。

## 判定・成果物・非対象

- 1件でも捕捉すれば「旧実装の N50R_CS_T50・135 MPa で CTSD NaN の発生を確認」とする。
  infのみを捕捉した場合は、NaN発生を確認したとは記載しない。
- 未検出は「指定seed・条件・観測範囲では未検出」とする。CTSD未評価なら未評価と明記する。
  NaNが一般に発生しないことの証明にはしない。
- 最初の1件で停止した結果から発生率や全候補への寄与を推定しない。
  有限寿命の採用だけで正常と判定せず、NaNの発生と最終寿命への影響を分ける。
- 最終報告はこのフォルダの `legacy_ctsd_nan_report.md` にまとめ、
  実行用 `.ps1`、条件、捕捉入力、再評価方法、確認範囲・未確認事項を示す。
- モデル式・粒層の進め方・採用条件の修正、他応力への展開、過去のseed未固定実行の完全再現は対象外。
