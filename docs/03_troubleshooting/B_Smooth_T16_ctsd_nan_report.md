# B_Smooth_T16: CTSD NaN 調査

## 結論

135 MPa の同条件を seed42 で局所再現したところ、すべり帯が到達していない粒界を
CTSD の幾何積分に含め、平方根の中身が負になる経路を確認した。
求めたすべり帯長さ `c` より深い粒界について、すべり帯長さの方程式ではその角度項が0になる一方、
CTSD 積分では同じ粒界の幾何積分を評価している。この粒界の扱いの違いが NaN を生じさせる。
同じ保存入力で、旧実装の局所関数も同じすべり帯長さ `c` と NaN を返した。

計算モデル本体の式・分岐は変更していない。追加したのは verification の捕捉・再評価用コードと入力 fixture である。

## 用語: 「根」は探索されたすべり帯長さ

この報告でいう「根」は、すべり帯長さ `c` を決める方程式 `F(c) = 0` の解を指す。
き裂深さ `a`、粒界位置、摩擦強度比を与え、この方程式を満たす `c` を数値計算で探すことを「根探索」と呼ぶ。
したがって、この箇所では「根＝方程式の解として探索されたすべり帯長さ `c`」である。

求めた `c` は、その後の CTSD 計算に入力する。
NaN が発生した `sqrt(c**2 - ad**2)` の「平方根」は、この方程式の解を指す「根」とは別である。

## 元の記録と調査範囲

- 元の `outputs/conditions/B_Smooth_T16/diagnostics/` には、135 MPa の4回分について
  CTSD と寿命積分値の非有限値が記録されていた。
- 元の実行は seed 未固定で、方位・粒界・根探索入力の全状態は保存されていない。
- 今回は同じ resources / cache を使い、seed42・135 MPa・最上位の1要素・対称領域1つを診断した。
  最初の非有限 CTSD を捕捉して停止し、通常の寿命計算を最後まで実行していない。
- これは元の乱数列の完全な再実行ではない。元の全イベントが同じ機序かは未確定である。

## 捕捉した直接原因

評価点 index=1（0始まり）で、以下を保存した。長さはモデル内の mm 単位。

| 値 | 捕捉値 |
| --- | --- |
| き裂深さ `a` | 0.014237724335527968 |
| 根探索から返ったすべり帯長さ `c` | 0.05253476091634689 |
| CTSD 積分の粒界数 `n+1` | 3 |
| 粒界1 | 0.024627415066859188 |
| 粒界2 | 0.03489031592979532 |
| 粒界3 | 0.05799976361244691 |

実際に `c` 以下にある粒界は2つだけである。
比較すべきなのは `c` という長さと粒界範囲そのものではなく、同じ `c` に対して
すべり帯長さの方程式と CTSD 積分が各粒界の項をどう扱うかである。
`c` は、その粒界まで到達しているかを判定する基準になる。
`_ctsd_geometry_integral(x, c, ad)` の3番目の粒界に対する計算では、
`c**2 - ad**2 = -0.0006040714745619924` となり、
`np.sqrt()` が `invalid value encountered in sqrt` を発生させて NaN を返した。
この非有限値が CTSD の和に入る。

### 幾何積分の変数名に関する注意

呼び出し元と幾何積分内で、`a` の意味が異なる。

```python
# _calculate_ctsd_value(): この a は「き裂深さ」
_ctsd_geometry_integral(a, c, rnList_L[i])

# _ctsd_geometry_integral(): x はき裂深さ、ad は粒界位置
if x == ad:
    a = (1 - 1e-3) * ad
else:
    a = ad

ca = np.sqrt(c**2 - a**2)
```

今回の第3粒界では `x != ad` なので、幾何積分内の `a = ad = 0.0579997636`。
したがって、668行の `sqrt(c**2 - a**2)` は、このケースでは
「すべり帯長さの二乗 − 粒界位置の二乗」の平方根を計算している。
き裂深さ `0.0142377243` を二乗して引く部分ではない。

コード上の経路は、**粒層の更新・分岐 → すべり帯長さの方程式 → CTSD の粒界数指定 →
幾何積分で負の平方根引数 → CTSD の非有限値検出 → 寿命積分への伝播**である。
これらの粒界の扱いを、モデルが意図する粒層の進め方に応じて統一する必要がある。

## 粒界数が食い違う経路

対象は `calculation/crack_life.py` の `_advance_ctsd_through_grain_layers()`、
`_solve_multilayer_slip_band_length()`、`_calculate_ctsd_value()` である。

1. 粒層を進め、新しい摩擦強度比 `sigma_fr[m+1]` を計算する。
2. 方程式を解いてすべり帯長さ `c` を求めるかの判定には、直前の `sigma_fr[m]` を使う。
   再現例の m=1 では、判定値が 0.9358201226、新しい比が 1.4552106799 である。
   判定値が1未満のため、この時点では方程式を解かず `c = 1.05 * thickness` を維持して次の層へ進む。
3. m=2 で初めてこの評価点の方程式を解き、すべり帯長さは `c = 0.0525347609` に短くなる。
   根探索の第3粒界の引数は `r3 / (c + 1e-10) = 1.1040264101`。
   `_safe_arccos()` はこれを1にクリップするため、第3粒界の角度項は0になる。
   方程式の残差は約 `-2.22e-16` で、数値的には方程式を満たす `c` が得られている。
4. 次のループで `c < 粒界4` を満たすと、進めた層数に基づいて粒界1～3を CTSD 積分へ渡す。
   求めたすべり帯長さ `c` が粒界3より短いことに合わせた範囲の調整・検査は行われず、
   平方根の中身が負になって NaN に達する。

到達済みの2粒界だけの方程式を局所評価すると、すべり帯長さ `c` の解は `0.0525347609163469` となった。
同じ `c` で CTSD 積分も2粒界だけにすると、有限値 `4.051369543536736e-05` を返す。
これは原因の切り分けのための反実仮想評価であり、修正済みの寿命・採用すべき CTSD 値という意味ではない。

## アルゴリズム上の不整合と粒層の進め方の統一

現在のアルゴリズムでは、粒層を進めた後に求めたすべり帯長さ `c` が、
それまで通過したと数えていた粒界より短くなる場合がある。
このとき、すべり帯長さの方程式では未到達粒界の角度項が0になる一方、
CTSD 積分では同じ粒界を評価対象に残している。
これは、同じすべり帯の到達範囲に対する粒界の扱いが計算段階によって異なる、
アルゴリズム上の不整合である。

この不整合を解消するには、**モデルが意図する粒層の進め方に応じて、
根探索の要否を判定する粒層、すべり帯長さ `c` の決定、通過済みと数える粒界、
CTSD 積分に含める粒界範囲を、一貫した手順に統一する必要がある。**
特に、新しい摩擦強度比 `sigma_fr[m+1]` を計算した後に直前の `sigma_fr[m]` で
根探索の要否を判定する手順と、その後に `c` が短くなった場合の粒界の扱いを、
同じモデル上の規則に基づいて定める必要がある。

今回の再現は、この統一が必要であることを示す。
どの粒層を判定対象とするか、粒界範囲をどう更新するかという具体的な手順は、
モデルの意図を確認して定めるものであり、単一の添字変更だけで解決すると確定したものではない。
今回の調査では計算式・分岐は変更していない。

なお、元の seed 未固定の全イベントが同じ経路によるものかは、この局所再現だけでは断定しない。

Fatigue-ferrite-pearlite-life-prediction-IJMS-2020 でも同様の実装であることを確認した。
